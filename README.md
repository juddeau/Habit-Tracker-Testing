# Habit Tracker 🔥

Веб-приложение для отслеживания привычек: бэкенд на **FastAPI** (SQLite), фронтенд — чистые **HTML/CSS/JS** без сборщиков и фреймворков.

![status](https://img.shields.io/badge/status-demo-orange)

---

## Возможности

- Создание, редактирование и удаление привычек (иконка + цвет)
- Отметка «выполнено сегодня»
- Текущий стрик (серия дней подряд), процент выполнения, общее число отметок
- Общая статистика по всем привычкам
- Тёмный адаптивный интерфейс

## Запуск

### 1. Бэкенд (FastAPI)

Требуется Python 3.9+.

```bash
cd habit-tracker/backend
python3 -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate

pip install -r requirements.txt

uvicorn main:app --reload --host 127.0.0.1 --port 8000
```

После запуска:
- API доступно на `http://127.0.0.1:8000`
- Интерактивная документация (Swagger) — `http://127.0.0.1:8000/docs`
- База данных `habits.db` создаётся автоматически в папке `backend/` при первом запуске

### 2. Фронтенд

Фронтенд — статические файлы, backend отдельно их не раздаёт. Проще всего поднять локальный веб-сервер прямо в папке `frontend/`:

```bash
cd habit-tracker/frontend
python3 -m http.server 5500
```

Открыть в браузере: **http://127.0.0.1:5500**

> Открывать `index.html` двойным кликом (`file://...`) не стоит — часть браузеров тогда блокирует запросы `fetch` к API. Через `http.server` всё работает штатно.

Адрес API прописан в `frontend/app.js` в константе:

```js
const API_BASE = "http://127.0.0.1:8000/api";
```

Если бэкенд запущен на другом хосте/порту — поменяйте эту строку.

### 3. Проверка

Откройте `http://127.0.0.1:5500`, добавьте привычку через кнопку **«+ Новая привычка»**, отметьте её выполненной. Если карточка появилась и обновилась статистика сверху — всё работает.

## API (кратко)

| Метод | Путь | Описание |
|---|---|---|
| GET | `/api/habits` | Список привычек с посчитанной статистикой |
| POST | `/api/habits` | Создать привычку `{name, icon, color}` |
| PUT | `/api/habits/{id}` | Обновить привычку |
| DELETE | `/api/habits/{id}` | Удалить привычку |
| POST | `/api/habits/{id}/checkins` | Отметить выполнение сегодня |
| DELETE | `/api/habits/{id}/checkins/{date}` | Убрать отметку за дату (`YYYY-MM-DD`) |
| GET | `/api/stats` | Общая статистика |

## Технологии

- **Backend:** Python 3, FastAPI, Uvicorn, SQLite (стандартная библиотека `sqlite3`)
- **Frontend:** HTML5, CSS3 (без препроцессоров), Vanilla JS (без сборки и фреймворков)

## ⚠️ Известные ошибки в приложении

Продукт содержит 5 намеренно внесённых ошибок для тестирования методом «чёрного ящика».

### Ошибка №1: Дублирующиеся отметки выполнения в один день
- **Тип ошибки:** логическая (backend + frontend)
- **Расположение:** `backend/main.py` (функция `add_checkin`), `frontend/app.js` (функция `toggleDone`)
- **Описание:** эндпоинт `POST /api/habits/{id}/checkins` добавляет новую строку в таблицу `checkins`, не проверяя, есть ли уже отметка за сегодня; ограничение `UNIQUE(habit_id, checkin_date)` в схеме БД отсутствует. Кнопка «Отметить выполненным» на фронтенде всегда отправляет POST.
- **Способ воспроизведения:** повторно нажать кнопку «Отметить выполненным» на одной привычке несколько раз подряд — `total_checkins` и `completion_rate` растут с каждым нажатием.
- **Способ исправления:** добавить `UNIQUE(habit_id, checkin_date)`; на фронтенде реализовать настоящий toggle (DELETE, если уже отмечено).

### Ошибка №2: Стрик считается на 1 больше, если сегодня ещё не отмечено
- **Тип ошибки:** логическая (backend)
- **Расположение:** `backend/main.py`, функция `calc_streak`
- **Описание:** строка `if last != today: streak += 1` добавляет единицу «про запас», как если бы привычка обязательно будет отмечена сегодня.
- **Способ воспроизведения:** привычка с отметками за два дня подряд (вчера и позавчера), но без отметки сегодня — покажет стрик 3 вместо 2.
- **Способ исправления:** убрать блок `if last != today: streak += 1`.

### Ошибка №3: Процент выполнения может превышать 100%
- **Тип ошибки:** логическая (backend)
- **Расположение:** `backend/main.py`, функция `calc_completion_rate`
- **Описание:** используется общее число строк `checkins` (включая дубликаты из ошибки №1), а не число уникальных дней; знаменатель `days_since_created` не включает день создания привычки.
- **Способ воспроизведения:** отметить привычку выполненной 3 раза в день создания — `completion_rate` покажет 300.0 вместо 100.
- **Способ исправления:** считать `len(set(checkin_dates))`; знаменатель — `days_since_created + 1`; ограничить итог `min(rate, 100)`.

### Ошибка №4: Удаление привычки не удаляет её отметки
- **Тип ошибки:** логическая (backend)
- **Расположение:** `backend/main.py`, функции `delete_habit` и `get_stats`
- **Описание:** при удалении привычки строки в таблице `checkins` не удаляются (нет `FOREIGN KEY ... ON DELETE CASCADE`), при этом `total_checkins` в `/api/stats` считается без учёта существования привычки.
- **Способ воспроизведения:** запросить `/api/stats`, удалить привычку с отметками, снова запросить `/api/stats` — `total_checkins` останется прежним.
- **Способ исправления:** при удалении выполнять `DELETE FROM checkins WHERE habit_id = ?`, либо включить `PRAGMA foreign_keys = ON` и `ON DELETE CASCADE`.

### Ошибка №5: Редактирование привычки может «перезаписать» другую при создании новой
- **Тип ошибки:** интерфейсная (frontend)
- **Расположение:** `frontend/app.js`
- **Описание:** переменная `editingHabitId` сбрасывается в `null` только в обработчике кнопки «Отмена»; закрытие модалки кликом по фону или Escape этого не делает.
- **Способ воспроизведения:** нажать ✎ у привычки → закрыть модалку кликом по фону или Esc (не «Отмена») → нажать «+ Новая привычка», заполнить и сохранить — вместо создания новой привычки произойдёт PUT для старой, и она перезапишется.
- **Способ исправления:** сбрасывать `editingHabitId = null` в самом `closeModal()`, либо явно вызывать сброс в `openCreateModal()`.
