# Habit Tracker 🔥

Веб-приложение для отслеживания привычек: бэкенд на **FastAPI** (SQLite), фронтенд — чистые **HTML/CSS/JS** без сборщиков и фреймворков.

![status](https://img.shields.io/badge/status-demo-orange)

---

## Возможности

- Создание, редактирование и удаление привычек (иконка + цвет)
- Отметка «выполнено сегодня»
- Текущий стрик (серия дней подряд), процент выполнения, общее число отметок
- Общая статистика по всем привычкам
- Тёмный адаптивный интерфейс

## Запуск

### 1. Бэкенд (FastAPI)

Требуется Python 3.9+.

```bash
cd habit-tracker/backend
python3 -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate

pip install -r requirements.txt

uvicorn main:app --reload --host 127.0.0.1 --port 8000
```

После запуска:
- API доступно на `http://127.0.0.1:8000`
- Интерактивная документация (Swagger) — `http://127.0.0.1:8000/docs`
- База данных `habits.db` создаётся автоматически в папке `backend/` при первом запуске

### 2. Фронтенд

Фронтенд — статические файлы, backend отдельно их не раздаёт. Проще всего поднять локальный веб-сервер прямо в папке `frontend/`:

```bash
cd habit-tracker/frontend
python3 -m http.server 5500
```

Открыть в браузере: **http://127.0.0.1:5500**

> Открывать `index.html` двойным кликом (`file://...`) не стоит — часть браузеров тогда блокирует запросы `fetch` к API. Через `http.server` всё работает штатно.

Адрес API прописан в `frontend/app.js` в константе:

```js
const API_BASE = "http://127.0.0.1:8000/api";
```

Если бэкенд запущен на другом хосте/порту — поменяйте эту строку.

### 3. Проверка

Откройте `http://127.0.0.1:5500`, добавьте привычку через кнопку **«+ Новая привычка»**, отметьте её выполненной. Если карточка появилась и обновилась статистика сверху — всё работает.

## API (кратко)

| Метод | Путь | Описание |
|---|---|---|
| GET | `/api/habits` | Список привычек с посчитанной статистикой |
| POST | `/api/habits` | Создать привычку `{name, icon, color}` |
| PUT | `/api/habits/{id}` | Обновить привычку |
| DELETE | `/api/habits/{id}` | Удалить привычку |
| POST | `/api/habits/{id}/checkins` | Отметить выполнение сегодня |
| DELETE | `/api/habits/{id}/checkins/{date}` | Убрать отметку за дату (`YYYY-MM-DD`) |
| GET | `/api/stats` | Общая статистика |

## ⚠️ Известные ошибки в приложении

В коде намеренно оставлено **5 ошибок** — для тренировки поиска багов / QA-практики. Все они воспроизведены и проверены вручную. Ниже — как их вызвать и как чинить.

### 1. Дублирующиеся отметки в один день (backend + frontend)

**Файлы:** `backend/main.py` (`add_checkin`), `frontend/app.js` (`toggleDone`)

Эндпоинт `POST /api/habits/{id}/checkins` просто вставляет новую строку в таблицу `checkins`, никак не проверяя, есть ли уже отметка на сегодня. В схеме БД также нет `UNIQUE(habit_id, checkin_date)`. На фронтенде кнопка «Отметить выполненным» всегда вызывает `POST`, а не проверяет текущее состояние `done_today` и не блокируется после нажатия.

**Как воспроизвести:** нажать кнопку «Отметить выполненным» несколько раз подряд (или обновить страницу и нажать снова). Внешне ничего не меняется (кнопка и так зелёная), но `total_checkins` и `completion_rate` в карточке растут с каждым кликом.

```bash
curl -X POST http://127.0.0.1:8000/api/habits/1/checkins
curl -X POST http://127.0.0.1:8000/api/habits/1/checkins
curl -X POST http://127.0.0.1:8000/api/habits/1/checkins
# total_checkins станет 3 вместо 1
```

**Как исправить:** добавить `UNIQUE(habit_id, checkin_date)` в таблицу `checkins` (или проверку `SELECT` перед `INSERT`), а на фронтенде — реальный toggle: если `done_today == true`, слать `DELETE /checkins/{today}`, иначе `POST`.

### 2. Стрик считается на 1 больше, если сегодня ещё не отмечено

**Файл:** `backend/main.py`, функция `calc_streak`

```python
if last != today:
    streak += 1
```

Эта строка добавляет единицу «про запас», как будто пользователь обязательно сделает привычку сегодня — даже если он её ещё не отметил.

**Как воспроизвести:** привычка с отметками за два дня подряд (вчера и позавчера), но без отметки сегодня, покажет стрик **3** вместо корректных **2**.

```bash
# создать привычку, вручную добавить в БД checkins на "вчера" и "позавчера" (без сегодняшней)
curl -s http://127.0.0.1:8000/api/habits | python3 -m json.tool
# в ответе streak будет на 1 больше реального числа дней подряд
```

**Как исправить:** убрать блок `if last != today: streak += 1` — стрик не должен увеличиваться авансом за ещё не выполненный сегодняшний день (по желанию — не сбрасывать его в 0, если сегодня «время ещё есть», но не завышать).

### 3. Процент выполнения может быть больше 100%

**Файл:** `backend/main.py`, функция `calc_completion_rate`

```python
rate = len(checkin_dates) / days_since_created * 100
```

Используется общее количество строк `checkins` (`len(checkin_dates)`), а не количество уникальных дней (`len(set(checkin_dates))`). В сочетании с багом №1 (дубли отметок) это легко даёт число больше 100%. Плюс `days_since_created` не включает день создания привычки, что само по себе занижает знаменатель.

**Как воспроизвести:** отметить привычку выполненной 3 раза в день её создания (см. баг №1) → `completion_rate` покажет `300.0`.

**Как исправить:** считать `len(set(checkin_dates))`, знаменатель — `days_since_created + 1`, и дополнительно ограничить итог `min(rate, 100)`.

---

### 4. Удаление привычки не удаляет её отметки — статистика «помнит» удалённые привычки

**Файл:** `backend/main.py`, `delete_habit` и `get_stats`

```python
conn.execute("DELETE FROM habits WHERE id = ?", (habit_id,))
```

Строки в `checkins`, принадлежащие удалённой привычке, никогда не удаляются (нет каскадного удаления и нет `FOREIGN KEY ... ON DELETE CASCADE`). При этом `GET /api/stats` считает `total_checkins` как `SELECT COUNT(*) FROM checkins` — без связи с таблицей `habits`. В итоге общее число отметок в статистике продолжает расти историей давно удалённых привычек, а в базе копится мусор.

**Как воспроизвести:**
```bash
curl -s http://127.0.0.1:8000/api/stats   # total_checkins: 5
curl -X DELETE http://127.0.0.1:8000/api/habits/1
curl -s http://127.0.0.1:8000/api/stats   # total_checkins всё ещё 5, хотя привычка 1 удалена
```

**Как исправить:** при удалении привычки выполнять `DELETE FROM checkins WHERE habit_id = ?`, либо включить `PRAGMA foreign_keys = ON` и объявить `FOREIGN KEY (habit_id) REFERENCES habits(id) ON DELETE CASCADE`.

### 5. Редактирование привычки может «утечь» в форму создания новой (только фронтенд)

**Файл:** `frontend/app.js`

Переменная `editingHabitId` выставляется в `openEditModal()`, но сбрасывается в `null` **только** в обработчике кнопки «Отмена» (`cancelBtn`). Закрытие модалки кликом по фону (`modalOverlay`) или клавишей `Escape` вызывает `closeModal()`, который этого не делает. `openCreateModal()` тоже не сбрасывает `editingHabitId`.

**Как воспроизвести:**
1. Нажать ✎ у любой привычки — откроется форма редактирования (`editingHabitId` = id этой привычки).
2. Закрыть модалку кликом по тёмному фону или клавишей `Esc` (не кнопкой «Отмена»).
3. Нажать «+ Новая привычка», заполнить как новую привычку и сохранить.

**Результат:** вместо создания новой привычки приложение отправит `PUT /api/habits/{старый id}` и **перезапишет** привычку из шага 1 новыми данными.

**Как исправить:** сбрасывать `editingHabitId = null` в самом `closeModal()` (а не только в обработчике «Отмена»), либо явно вызывать сброс в `openCreateModal()`.
